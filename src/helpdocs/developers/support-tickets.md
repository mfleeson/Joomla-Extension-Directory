# Support tickets for developers

The JED ticket system is primarily for developers with listings on the JED. It is how you talk to
the JED team about your listings. (For how to open, read and reply to tickets in general, see
[Reporting and tickets](../general-users/reporting-and-tickets.md).)

## Tickets opened for you automatically

You do not have to open a ticket for the normal workflow - the JED opens one when:

| Event | Ticket |
|---|---|
| You submit a new listing | "New listing submitted: *name*" |
| You edit a listing | "Listing *name* was edited by its developer" |
| You respond to a review | "A developer response was submitted to the review *title*" |
| A link on your listing stops working | "*name*: the *Download link* has stopped working" - see [broken link notices](security-vel-and-abandonware.md#broken-link-notices) |

These tickets appear in **My Dashboard > My Tickets**; the JED team's replies and decisions about
your listing arrive there and by e-mail. When a submission or edit is not approved, the ticket
receives a "Not approved: *code*" message with the reviewer's notes and waits for your reply.

## Choosing a ticket type

When you open a ticket yourself (**My Dashboard > My Tickets > Create a ticket**), pick the type
that matches - the JED team routes tickets by type:

| Ticket type | Use it for |
|---|---|
| **New Listing Support** | A submission that is not yet approved - e.g. "I have fixed the NM1 issue, please check again" |
| **Current Listing Support** | An approved listing - e.g. changes you need the team to make, ownership questions, licensing questions |
| **Unpublished Support** | A listing that was **blocked** - e.g. "the broken link is fixed", "here is the VEL resolved link". (A listing *you* took offline you can put back online yourself from the dashboard.) |
| **Reported Review** | A review of your extension that breaks the guidelines (use *Report review* on the dashboard instead - it links the review for you) |
| **Site Technical Issues** / **Joomla Site Issue** | Problems with the JED website itself |

The rejection and block e-mails from the JED team tell you which type to use when you have fixed
something.

## Tips

- Name the listing and, if relevant, the reason code.
- Keep one topic per ticket and reply in the same ticket rather than opening new ones.
- When the status is **Awaiting User**, the team is waiting for you.
- Never put security vulnerability details in a ticket - use the VEL forms.
